# Digest: wrapper technology and how a Phaser 4 game runs inside it (round 1, track 1)

Decision served: how to turn the Phaser 4 + TS + Vite co-op browser game into iOS and Android apps (solo hobby dev, Mac, iPhone, Xiaomi Mi 11i). Accessed 2026-11-23. Evidence was gathered by web search and fetch. Many entries rest on search-result snippets and were not read in full; confidence is lowered to match.

### 2. WebGL performance inside the wrappers

- On iOS, WKWebView runs JavaScript with JIT. In-process JavaScriptCore does not. Apple DTS and WebKit staff both say to use WKWebView if you need JIT | https://developer.apple.com/forums/thread/728165 ; https://app.lucid.co/techblog/2019/01/03/javascriptcore-10-months-later | Apple Developer Forums / Lucid | 2019–2023 | accessed 2026-11-23 | medium-high | performance
- An Apple forum answer says WKWebView and Safari should have the same JS feature support. This is a forum reply, not documentation | https://developer.apple.com/forums/thread/728165 | Apple Developer Forums | ~2023 | accessed 2026-11-23 | medium | compat
- A developer running WebGL games in WKWebView reported low framerates and poor thermals for "the first few minutes", which they blamed on the OMG JIT tier. They asked to tune `useOMGJIT` and got no answer in the result | https://developer.apple.com/forums/thread/721315 | Apple Developer Forums | ~2022 | accessed 2026-11-23 | low-medium | performance
- Possible iOS 27 issue: a WebKit bug report says JS/Wasm run without JIT on plain-http origins but at full speed on https, in both Safari and WKWebView. It is unconfirmed. Capacitor serves local content from `capacitor://` (iOS) and `https://localhost` (Android); whether the custom scheme is affected is unknown | https://bugs.webkit.org/show_bug.cgi?id=324968 | WebKit Bugzilla | 2026 | accessed 2026-11-23 | low | performance
- WebGPU is enabled by default from iOS 26 / Safari 26. An Apple-affiliated forum reply says Safari feature flags do not apply to WKWebView, which gets a feature only once it is enabled by default; that implies WKWebView has WebGPU on iOS 26+. There are reports of WebGPU bugs and a WKWebView GPU-process crash on iPhone 15 with iOS 26.4. This does not change much for Phaser 4, which renders with WebGL | https://developer.apple.com/forums/thread/770862 ; https://developer.apple.com/forums/thread/822200 ; https://webkit.org/blog/17541/webkit-features-for-safari-26-1/ | Apple / WebKit | 2025–2026 | accessed 2026-11-23 | medium | compat
- Android System WebView "shares the same rendering engine as Chrome for Android" and ships as its own APK, updated separately from the OS through Play. It has some behaviour that differs from Chrome | https://developer.chrome.com/docs/webview | Google Chrome for Developers | updated 2024-12-18 | accessed 2026-11-23 | high | compat
- Capacitor's System Bars docs warn about a WebView bug in versions below 140 that breaks `safe-area-inset-*` env values. Old WebViews matter for safe-area handling | https://capacitorjs.com/docs/apis/system-bars | Capacitor | v8 docs | accessed 2026-11-23 | high | compat
- The only WebView vs Chrome WebGL number found is an old single-device anecdote (Khadas board, ~40 fps in Chrome vs ~20 fps in WebView). It does not generalise | https://forum.khadas.com/t/webview-webgl-performance-problem/1706 | Khadas forum | old (~2018) | accessed 2026-11-23 | low | performance
- Phaser 3.60 added a dedicated mobile render pipeline, chosen automatically on iOS/Android. Phaser's tests found iOS dropped below 60 fps first as texture count grew. Phaser 4 inherits this lineage; that Phaser 4 behaves the same is unverified | https://unpkg.com/phaser@4.2.1/changelog/v3/3.60/MobilePerformance.md | Phaser | 2023 | accessed 2026-11-23 | medium | performance

### 3. Native polish (plugins)

- The official Capacitor v8 plugin list includes App, Haptics, Screen Orientation, Splash Screen, Status Bar, System Bars, Keyboard, Device, Network, Preferences and Privacy Screen (38 in total). Keep Awake is not official | https://capacitorjs.com/docs/apis | Capacitor | v8 docs | accessed 2026-11-23 | high | ecosystem
- System Bars, new in 8.0.0 and bundled in @capacitor/core, has `hide()`/`show()` for StatusBar and NavigationBar ("navigation bar on Android or the gesture bar on iOS"). On Android it handles insets through `insetsHandling` (default `css`, which injects `--safe-area-inset-*` variables). The docs do not mention the iOS home indicator, and there is no explicit "immersive" mode | https://capacitorjs.com/docs/apis/system-bars | Capacitor | v8 docs | accessed 2026-11-23 | high | compat
- Keep screen awake needs a community plugin: @capacitor-community/keep-awake, Capawesome keep-awake (Android/iOS/web), or @capgo/capacitor-keep-awake | https://www.npmjs.com/package/@capacitor-community/keep-awake ; https://capawesome.io/docs/sdks/capacitor/keep-awake/ ; https://capgo.app/docs/plugins/keep-awake/ | community | n/a | accessed 2026-11-23 | medium-high | ecosystem
- For Android immersive mode, community options are Capawesome Navigation Bar (Android-only; its docs suggest hiding the bar for games) and squareetlabs capacitor-android-edge-to-edge (has an immersive option). @boengli/capacitor-fullscreen is alpha. Official System Bars `hide()` may be enough; untested | https://capawesome.io/docs/sdks/capacitor/navigation-bar/ ; https://github.com/squareetlabs/capacitor-android-edge-to-edge | community | n/a | accessed 2026-11-23 | medium | ecosystem
- iOS silent switch: Web Audio is "ambient" by default and is muted by the ringer switch. Setting `navigator.audioSession.type = "playback"` fixes this, according to a WebKit engineer and confirmed by a reporter. AudioContext may still be suspended in the background, and `"transient"` and `"play-and-record"` have side effects (iOS 16.3–18 reports) | https://bugs.webkit.org/show_bug.cgi?id=237322 ; https://www.w3.org/TR/audio-session/ | WebKit Bugzilla / W3C | 2022–2024 | accessed 2026-11-23 | medium | compat
- Older Apple forum threads report that WKWebView ignores the host app's AVAudioSession category. Setting a native category from a plugin may not change WebView audio behaviour | https://developer.apple.com/forums/thread/24464 ; https://developer.apple.com/forums/thread/71889 | Apple Developer Forums | old (2015–2017) | accessed 2026-11-23 | low | compat
