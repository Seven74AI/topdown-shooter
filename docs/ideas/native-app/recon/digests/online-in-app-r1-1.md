# Digest: online play inside a Capacitor app (r1-1)

Decision served: wrapping the Phaser + Colyseus 0.18 co-op game (server https://example-game.io/api, invites https://example-game.io/j/ABCD) as iOS/Android apps with Capacitor while the web version keeps working.
Accessed 2026-11-23. About 18 tool calls. Web sources only. No project files were read.

## Findings

### Q1: Origin, CORS, CapacitorHttp, WSS
- The default local scheme on iOS is `capacitor` and it is configurable with `server.iosScheme`. It cannot be set to schemes WKWebView already handles (http/https). | https://capacitorjs.com/docs/config | Ionic/Capacitor | undated (v8 docs) | accessed 2026-11-23 | high | compat
- `server.androidScheme` defaults to `https`. The docs warn that values other than http/https can break routing, and that custom schemes cannot change the URL path as of WebView 117. | https://capacitorjs.com/docs/config | Ionic/Capacitor | undated (v8 docs) | accessed 2026-11-23 | high | compat
- `server.hostname` defaults to `localhost`, and the docs recommend keeping it because it allows the use of Web APIs. So the web-view origins are `capacitor://localhost` (iOS) and `https://localhost` (Android), with the hostname swapped if you change it. | https://capacitorjs.com/docs/config | Ionic/Capacitor | undated | accessed 2026-11-23 | high | compat
- Ionic's CORS page lists iOS `capacitor://localhost` and Android `http://localhost`. The Android value predates the https default, so it looks stale. It recommends allowlisting these origins and reflecting the request `Origin` in `Access-Control-Allow-Origin`, and handling OPTIONS preflight. | https://ionicframework.com/docs/troubleshooting/cors | Ionic | undated | accessed 2026-11-23 | high (pattern) / medium (Android value) | compat
- A Capacitor 7-to-8 Android upgrade thread treats `https://localhost` as the origin the API must allow. The "hostname ignored" problem turned out to be a config syntax error. | https://forum.ionicframework.com/t/capacitors-server-hostname-configuration-option-not-working-after-upgrade-to-capacitor-8/250440 | Ionic Forum | 2026-01-21 | accessed 2026-11-23 | medium | compat
- A Traccar user saw a WebSocket that worked in the browser fail on iOS because the Origin changed to `capacitor://localhost`. Another report says cookies were not sent on the WebSocket HTTP Upgrade from Capacitor. This is secondary: it came from a search summary and the threads were not opened. | https://www.traccar.org/forums/topic/websocket-issue/ | Traccar forum | undated | accessed 2026-11-23 | low-medium | compat
- CapacitorHttp patching of `fetch`/XHR is off by default (`CapacitorHttp.enabled`). Its docs do not cover WebSockets, so the Colyseus WebSocket always goes through the WebView's own stack and sends the web-view Origin. | https://capacitorjs.com/docs/apis/http | Ionic/Capacitor | undated | accessed 2026-11-23 | high (scope) | compat
- With CapacitorHttp on Android, the Origin header arrived empty or undefined at the server, while iOS sent `capacitor://localhost`. A reply says CapacitorHttp adds latency and recommends plain fetch. | https://forum.ionicframework.com/t/capacitorhttp-on-android-is-sending-empty-origin/247643 | Ionic Forum | 2025-04-23 | accessed 2026-11-23 | medium | compat
- Implication (inference from the above): if the Colyseus server checks origins, add `capacitor://localhost` and `https://localhost` to the allowlist, plus `http://localhost` for older builds. If `/api` HTTP matchmaking uses fetch, CORS must allow the same origins. Do not rely on cookies for WebSocket auth; pass a token in the join options. | derived | - | - | - | medium | compat

### Q2: Deep links (Universal Links / App Links)
- iOS setup: enable the Associated Domains capability. Host an extension-less `apple-app-site-association` at `https://domain/.well-known/` listing `APPIDPREFIX.BUNDLEID` under `applinks`. Add `applinks:domain` in Xcode. If the app is not installed, the link opens the website. | https://capacitorjs.com/docs/guides/deep-links | Ionic/Capacitor | undated (v8 docs) | accessed 2026-11-23 | high | process
- Android setup: put `/.well-known/assetlinks.json` (relation `delegate_permission/common.handle_all_urls`, package name, and SHA256 cert fingerprint) on the domain. Add an intent filter with `android:autoVerify="true"`, VIEW/DEFAULT/BROWSABLE, the https scheme and the host. Verification does not require the app to be in the store. | https://capacitorjs.com/docs/guides/deep-links | Ionic/Capacitor | undated | accessed 2026-11-23 | high | process
- Routing is the app's job: `App.addListener('appUrlOpen', e => ...)` parses `e.url` and navigates. `getLaunchUrl()` returns the launch URL. The docs say `appUrlOpen` covers Universal Links and App Links. | https://capacitorjs.com/docs/apis/app | Ionic/Capacitor | undated | accessed 2026-11-23 | high | compat
- In-app browsers (Instagram, Facebook, TikTok, Gmail) often do not hand Universal Links to iOS, so the page opens in the webview instead of the app. Vendor sources disagree on WhatsApp. Pasting the link into a browser's address bar never triggers a Universal Link. Common fallbacks are a landing page with a second tap or "Open in app" button, or a custom scheme. | https://www.airbridge.io/en/blog/deep-link-opened-in-social-app-browser-what-breaks ; https://www.branch.io/resources/blog/why-deep-links-break-in-production-and-what-to-do-about-it/ | Airbridge / Branch (vendors) | undated | accessed 2026-11-23 | medium | compat
- Implication: `/j/ABCD` should stay a working web page that joins in the browser and offers an "Open in app" button, so a failed hand-off still works. | derived | - | - | - | medium | process

### Q3: Version skew, live updates, force update
- Capgo channels point at a JS bundle. A per-channel "Disable Auto Update" strategy (major/minor/patch/metadata with `--min-update-version`) blocks bundles that are incompatible with the device's native build (`version_build`). Devices can be assigned by forced mapping, cloud override, `setChannel()` in the app (plugin 8.0.0+ or 5/6/7.34.0+), or `defaultChannel` in config. | https://capgo.app/docs/live-updates/channels/ | Capgo | undated | accessed 2026-11-23 | high | process
- Ionic Appflow stopped selling to new customers in February 2025 and is reported to reach end of life on 2027-12-31. Both sources are competing vendors, and Ionic's own article was not read. | https://capawesome.io/blog/migrating-from-ionic-appflow-to-capawesome-cloud/ ; https://capgo.app/docs/upgrade/from-appflow-to-capgo/ | Capawesome / Capgo | undated | accessed 2026-11-23 | medium | policy
- `@capawesome/capacitor-app-update`: `getAppUpdateInfo()` returns current and available versions. On Android it also returns `updatePriority`, `immediateUpdateAllowed`, `flexibleUpdateAllowed` and `clientVersionStalenessDays`. Immediate and flexible in-app updates are Android-only. On iOS the plugin only reports the store version and `openAppStore()`. Only Capacitor 8.x is actively supported. Live updates need the separate Live Update plugin. | https://capawesome.io/plugins/app-update/ | Capawesome | undated | accessed 2026-11-23 | high | compat
- Play In-App Updates offers an "immediate" flow: a full-screen forced update and restart, handled by Play. A "flexible" flow downloads in the background. It requires Android 5.0+ and Play-distributed builds. | https://developer.android.com/guide/playcore/in-app-updates | Google | undated | accessed 2026-11-23 | high | compat
- App Review Guideline 2.5.2 forbids downloading code that "introduces or changes features or functionality". Guideline 4.7 permits HTML5/JS mini games and mini apps under conditions. JS live updates for bug fixes and balance changes are commonly treated as allowed, but the exact PLA clause (3.3.x) was not retrieved. | https://developer.apple.com/app-store/review/guidelines/ | Apple | undated | accessed 2026-11-23 | medium | policy
- Guideline 4.2 says an app must go beyond a "repackaged website". This is a review risk for a thin Capacitor wrapper. | https://developer.apple.com/app-store/review/guidelines/ | Apple | undated | accessed 2026-11-23 | high | policy
- Implication: the server's balance-version check should give clients a structured "update required" reply (live-update bundle, or store build if the native version is too old) instead of a bare refusal. Live updates via a Capgo or Capawesome channel can close the 1–3 day review gap for JS-only balance changes. | derived | - | - | - | medium | process

### Q4: Backgrounding and resume
- The `pause` event fires on iOS `didEnterBackgroundNotification` and Android `onPause`. `resume` fires on iOS `willEnterForegroundNotification` and Android `onResume`. On the web these follow `visibilitychange`. Android may kill the app under memory pressure (see `appRestoredResult`). | https://capacitorjs.com/docs/apis/app | Ionic/Capacitor | undated | accessed 2026-11-23 | high | compat
- WKWebView WebSockets drop as soon as the app is backgrounded. | https://developer.apple.com/forums/thread/681892 | Apple Developer Forums | ~2021 | accessed 2026-11-23 | medium | compat
- WebKit bug 308073 (Feb 2026): on iOS 26.3 Safari, a new WebSocket after resume can get stuck at readyState 0 with no events. In the same report, Brave's WKWebView reconnected immediately. Older bug 228296 (iOS 15): closing the socket manually on background avoided the broken state. | https://bugs.webkit.org/show_bug.cgi?id=308073 ; https://lists.webkit.org/pipermail/webkit-unassigned/2021-December/1010124.html | WebKit Bugzilla | 2026-02 / 2021-12 | accessed 2026-11-23 | medium | compat
- Android: background JS execution and timers in a WebView are not reliable, and WebSockets are typically dropped when the app is suspended. Evidence is a third-party vendor article and secondary reports. `@capacitor/background-runner` is a separate headless JS context and cannot keep the WebView's socket alive. | https://capgo.app/blog/how-background-tasks-work-in-capacitor/ ; https://capacitorjs.com/docs/apis/background-runner | Capgo / Capacitor | undated | accessed 2026-11-23 | low-medium | compat
- Implication: on `pause`, close the Colyseus connection deliberately or let it drop. On `resume`, reconnect with `client.reconnect(reconnectionToken)` inside the server's `allowReconnection` window, with a full rejoin as fallback. The Colyseus API names come from my own knowledge and were not verified this run. | derived | - | - | - | medium | compat

### Q5: Share sheet and push notifications
- `@capacitor/share`: `share({title, text, url, files, dialogTitle})` opens the native share sheet. `canShare()` reports support. On the web it falls back to the Web Share API, which the docs call "spotty". The same code serves both platforms, so the effort is small. | https://capacitorjs.com/docs/apis/share | Ionic/Capacitor | undated | accessed 2026-11-23 | high | compat
- `@capacitor/push-notifications`: on iOS, enable the Push capability and add AppDelegate hooks; the token returned is an APNs token, not FCM. On Android, set up a Firebase project with `google-services.json`; the token is an FCM token. Android 13+ needs `requestPermissions()`. There is no iOS silent push. Doze can delay delivery. Data-only messages are not handled when the app is killed. | https://capacitorjs.com/docs/apis/push-notifications | Ionic/Capacitor | undated (v8) | accessed 2026-11-23 | high | process
- Implication: push needs a backend sender for both APNs and FCM tokens (two token types), plus a token store and permission UX. That is moderate effort. For a friend group, a share link sent through their existing messenger probably covers most of the value. This is a judgment, not evidenced. | derived | - | - | - | low | process

### Q6: Networking advantage or disadvantage
- No primary source found comparing Capacitor WebView networking or timer throttling with browser tabs. Backgrounding behaviour (Q4) appears no better than a browser tab and is possibly stricter on iOS. In the foreground the WebView is the same engine as the browser (WebKit on iOS, Chromium System WebView on Android), so the transport should be equivalent. This is an unverified belief. | - | - | - | accessed 2026-11-23 | low | compat
- CapacitorHttp adds latency compared with plain fetch, per a forum reply (anecdotal). | https://forum.ionicframework.com/t/capacitorhttp-on-android-is-sending-empty-origin/247643 | Ionic Forum | 2025-04-23 | accessed 2026-11-23 | low | compat
