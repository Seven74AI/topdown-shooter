## 2. What went well

- **The money core held against real PostgreSQL.** Reviewers wrote probes for 7.2, 7.3, 7.4+7.5 and 7.12 and ran them on PostgreSQL 16 [V: probe folders]. Results:
  - 10× concurrent double-submit → 1 bank (log :118);
  - parallel buys → 1 ok + `not_enough`, with no deadlock against banking (log :129);
  - one item per run even with 12 concurrent banks (log :165).
- **One shared fix became a pattern.** The "told it failed, but it committed" family appeared in 7.2 M1, RR-M1 and 7.3 F1. It was fixed once, as `db/boundedTx.ts › boundedTransaction`: the reported status always equals what committed (log :134). Then 7.3, 7.6 and 7.10 reused it [V].
- **Identity and abuse checks were thorough.** Reviewers attacked identity directly:
  - 7.1: 137 ticket variants refused (log :108);
  - 7.6: identical error messages and timing, IP limits, 60-bit recovery codes, merge-once ×10 (log :154);
  - 7.9: look ownership against unowned parts, unicode, `__proto__` and a tampered session (log :121).
- **Early starts by real file overlap saved the critical path.** 7.1 and 7.9 built their non-join tasks while 8.1 was still in review (OR-4). 7.2, 7.3 and 7.9 built on gated branches (OR-13, OR-15) [V: log :47, :54, :56].
- **Layout tests found real bugs.** Real-DOM layout tests were added in 7.2 L2, 7.3 B15 and 7.12 M5. The 7.12 M5 layout test caught a second missing `}`, and `cssBraces.test.ts` now guards against that class of bug (log :171) [V].
- **The re-review cap ended the fix loop.** The designer's cap (log :63) closed 7.2 after round 2 and closed 7.4+7.5, 7.6, 7.9 and 7.10 with main-session checks. No later finding has traced back to a fix approved by a main-session check [I: none found in the run log through 00:32].

## 4. What hurt

### H1. Master CI was red from 09:28 to 13:10, because the local gate skipped steps that only CI runs

- **Cause 1:** 7.1 made the compose file require `POSTGRES_PASSWORD` and `SESSION_SECRET`, so CI's docker smoke failed.
- **Cause 2:** 7.3 F11 put `.dev-gear` in `overlay.css`, so the release CSS failed `noCheatsInRelease`.
- **Why nobody saw it:** "Local gate never ran those two CI-only steps" (log :178) [V]. Every landing in that window had a green local gate: 7.2, 7.9, 7.3 and 7.4+7.5. Each "→ ON MASTER" line in log :149–:176 is about the local gate. **Nobody read master's CI until the designer flagged it** [V].
- **The fix:** `287bfad` moved the rule to `DevCheats.css` and added throwaway secrets (log :178).
- **The process change:** the designer moved the team to PRs with CI as the gate. Docs-only changes skip CI (log :179). The `master gate` ruleset was set up at 14:45 (log :187).
- **A second hidden gap:** the CI-speed diagnosis found that **Playwright DOM checks silently skipped in CI**. 123 tests had never run there (log :180, :186) [V]. So Epic 7's real-DOM layout tests ran only locally until PR #10.
- **Lesson:** the gate that decides must be the gate that runs. A local "gate" that is a subset of CI is a guess.

### H2. The real backend is tested only by opt-in tests

- PGlite has a single connection, so deleting `FOR UPDATE` failed no test (7.2 Debug Log :149) [V].
- The opt-in real-PostgreSQL files exist (`realPostgres.test.ts`, `realPostgresAccounts.test.ts`, `realPostgresSaves.test.ts`), but CI skips them (`:26`) [V].
- Every money and lock guarantee in §2 therefore rests on runs that reviewers and builders did by hand.
- Never run anywhere: PostgreSQL 18 `transaction_timeout` (7.2 Not verified :220), Docker compose, deploy migrations, and `backup.sh`/`restore.sh` (7.1 Not verified :214) [V].

### H3. The records lag the work

- 7.3's file records only re-review 1 (:294). The run log has the clean re-review 2 (log :141).
- 7.12's file has headings "for round 2" (:384, :394) but no round-2 verdict. The approval is in log :176.
- 7.7's Completion Notes (:111) still say "D1–D3 pending". They were accepted in decisions-progress:3 [V].
- sprint-status lines 171 and 180 are right. The story files are not.
- Epic 6 A9 (text sweep) covered numbers, not review history.

### H4. Shared-shape stories collided at landing

See §3. **[I]** A story writer who knows two stories will touch the same object (the `progress` reply, the state field order) should name one story as the owner of that shape and have the other build on it. Epic 7's writer didn't. That was fine for building and expensive for landing.

## 10. Actions for the next builders (brief lines)

```
FROM THE EPIC 7 RETRO (_bmad-output/implementation-artifacts/epic-7-retro-2026-11-26.md §9)
1. CI IS THE GATE: your local gate:fast is a smoke test. A story is ready only when its PR's `gate` check is green; never call a step "CI-only" and skip it.
2. REAL DATABASE: money, lock or uniqueness code needs a real-PostgreSQL case (realPostgres*.test.ts), not just PGlite. PGlite has one connection and hides lock bugs.
3. MIGRATIONS: never rename a parallel migration; regenerate it after the other one lands (Drizzle skips an older `when`).
4. SHARED SHAPES: if your story adds to the session reply, the state field order or the migration list, check whether another open story does too; build on the owner story's branch.
5. RECORD TO THE END: the story file holds every review and re-review verdict, including the last one, before you hand back for landing.
```
