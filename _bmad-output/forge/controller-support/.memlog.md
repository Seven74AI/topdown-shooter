- (note) GDD lists controller support under Not planned; desktop KBM is a bonus; mobile-first. Story files 7.3/7.6 claim menuInput.ts does keyboard/gamepad menu nav, but menuInput.ts has no gamepad code (no getGamepads anywhere in client).
- (direction) Reframe: not desktop console-style play. The target is the phone (mobile browser) with a Bluetooth Xbox/PS pad. This fits the mobile-first pillar, unlike the GDD's 'Not planned' line, which is about controller support in general.
- (decision) Controller-only: every part of a run (waves, build phase, shop, lobby, vote, menus) must be playable without touching the screen.
- (assumption) Build phase can reuse Story 5.23's no-pointer path: the ghost carries in front of the walking survivor; R rotate, Space place, digits 1-7 pick, M pick up, Z undo. Gamepad = remap plus a way to choose 1 of 7 tiles.
- (crack) Text entry: player name (topdown.name) and 4-letter room code are typed into <input> fields; a pad has no keyboard.
- (crack) Idea 'controller selects a field -> phone keyboard opens': (1) gamepad presses are not user activation, so focus() from a gamepad poll likely won't raise the soft keyboard on iOS Safari / Android Chrome (to verify on device); (2) even if it opened, the soft keyboard is typed by touch, so it isn't controller-only.
- (direction) User accepts touch typing on the phone keyboard; wants the controller only to select/focus fields. If it works, the scope shrinks to controller focus navigation across Preact screens plus focus() on inputs.
- (assumption) Researched: Chrome counts a getGamepads() poll with a button >50% pressed as user activation, so focus() in that same call may raise the Android soft keyboard (unconfirmed). Safari/WebKit has no gamepad user activation, and iOS needs activation to show the keyboard, so on iPhone the keyboard likely won't open from the pad.
